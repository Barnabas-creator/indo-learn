# 内容线上化设计（2026-08-31）

## 背景

今天的内容是**整包加密、随站点下发**：`tools/pack-content.mjs` 把 `content-src/` 打成
六个 `data/<version>/*.enc`，跟着 Pages 一起发布；用户登录后 Worker 下发一把内容密钥
（CEK），浏览器本地解密整包。

这套设计当初是为「无后端也能授权」服务的。后端（Workers + D1）在 2026-08-21 上线后，
它剩下四个问题：

1. **防拷贝**：密文全集躺在站点上，一把 CEK 开全部。任何一个正常用户都能把 2020 条
   词库一次性导出。
2. **更新麻烦**：改一个错字要走「打包 → 灌密钥 → 升 sw.js 缓存名 → 推两个站点」四步，
   顺序不能乱，漏一步全体用户卡在登录页（见 README「发布铁律」）。
3. **首屏重**：整包 1.1 MB 密文在解锁时一次性拉齐，且六个模块互相不独立——只想背单词
   也要等语法和教材。
4. **权限做不细**：只有「有钥匙 / 没钥匙」两态，做不了免费试吃、分级定价。

## 目标

内容改为**按单元、按需、鉴权下发**，源头放 D1，Worker 出接口，前端本地缓存已取过的单元。

**非目标**：不改 UI 布局与文案；不动账号/激活码体系；不做进度记录（项目一贯要求）；
不改 assets（图、音频）的分发方式。

## 一、内容切成单元

| 模块 | 单元粒度 | 数量 | 单个大小 | unit_id 取值 |
| --- | --- | --- | --- | --- |
| packs | 一个词包 | ~202 | 2–3 KB | `freq-beginner-001` 等现有包 id |
| roots | 一个词根包 | 20 | ~3 KB | 现有包 id |
| dialogs | 一段对话 | 10 | ~10 KB | `sapaan` 等现有 id |
| grammar | 一个语法模块（含其下全部课） | 8 | ~38 KB | `phonetic` 等现有 id |
| course | 一个教材单元（含其下全部课） | ~10 | ~12 KB | `u01` 等现有 id |
| listening | 整块 | 1 | 12 KB | `all` |

粒度按「用户一次点开要看的东西」定，不按「文件现在怎么存」定。grammar / course 不切到
课一级：一个模块 38 KB，切了只是让翻课时多几十个请求，防拷贝上也没多挡什么。

## 二、后端

### 数据模型

```sql
CREATE TABLE content (
  module    TEXT NOT NULL,          -- packs / roots / dialogs / grammar / course / listening
  unit_id   TEXT NOT NULL,
  tier      TEXT NOT NULL,          -- 'free' | 'paid'
  version   TEXT NOT NULL,          -- 内容版本，随每次 push 递增
  title     TEXT,                   -- 清单页要显示的标题；packs / roots 留空（标题在 catalog.js 里）
  body      TEXT NOT NULL,          -- 单元正文，JSON 字符串
  PRIMARY KEY (module, unit_id)
);

CREATE TABLE content_meta (         -- 单行表，存全局内容版本
  id      INTEGER PRIMARY KEY CHECK (id = 1),
  version TEXT NOT NULL,
  built_at INTEGER NOT NULL
);

CREATE TABLE content_hits (         -- 防批量扒
  subject TEXT NOT NULL,            -- 'acct:<id>' 或 'ip:<addr>'（匿名取 free 单元时）
  day     TEXT NOT NULL,            -- YYYY-MM-DD (UTC)
  n       INTEGER NOT NULL,
  PRIMARY KEY (subject, day)
);
```

`lib/catalog.js`（词包骨架，明文，构建产物）保持不变——它只有标题和顺序，本来就公开，
且首页要在没登录时就渲染出来。

### 路由

两条新路由，都挂在现有 Worker 上：

**`GET /content/index`**

返回各模块的单元清单：

```json
{
  "version": "c1",
  "modules": {
    "packs":   [{ "id": "freq-beginner-001", "tier": "free" }],
    "dialogs": [{ "id": "sapaan", "tier": "free", "title": "打招呼" }]
  }
}
```

- 不带 token：只返回 `tier='free'` 的单元。
- 带有效 token 且账号 active / 试用期内 trial：返回全部。
- 清单只有 id / tier / title，没有正文。

**`GET /content/:module/:id`**

返回 `{ "version": "c1", "body": … }`，`body` 是解析好的 JSON。

访问规则（自上而下，命中即返回）：

| 情况 | 结果 |
| --- | --- |
| module/id 不存在 | 404 `not_found` |
| 单元 `tier='free'` | 放行（不需要 token） |
| 无 token / token 失效 | 401 `unauthorized` |
| 账号 disabled | 403 `account_disabled` |
| 账号 trial 且已过期 | 403 `trial_expired` |
| 账号既非 active 也非 trial | 403 `not_activated` |
| 当日请求数超限 | 429 `rate_limited` |

复用 `requireAccount()` 与 `handleContentKey` 里那套 trial 判定，不新写一套。

### 限流

每次 `/content/:module/:id` 命中给 `content_hits` 当天的行 +1（`INSERT … ON CONFLICT DO
UPDATE`）。登录用户按账号计，匿名按 IP 计（`cf-connecting-ip`）。

| 主体 | 每日上限 | 理由 |
| --- | --- | --- |
| 账号 | 400 | 全站单元约 250 个。正常人一天翻不到 400 个，扒全集要连着两天且留痕 |
| 匿名 IP | 60 | free 层本来就没几个单元，60 次足够试吃 |

超限返回 429，并写一条 `error_log`（`kind='rate_limited'`）——这是「有人在扒」的信号，
不是普通错误，值得能查到。

限流是**计数不是配额**：不阻止正常使用，只把「一次性导出全集」变成看得见、拖得慢的事。
真要防死做不到（内容终究要送到浏览器里），这一点写在 README「安全边界」里。

## 三、前端

### 新 provider

新增 `lib/server-provider.js`，`lib/config.js` 的 `AUTH_MODE` 取值改为 `'server'`（唯一值，
见「下线清单」）。接口从整包改成按需：

```js
{
  init, register, login, activate, requestCode, lock, lastRevokeReason,  // 与今天一致
  getIndex(),                    // → { version, modules: { packs: [...], … } }
  getUnit(module, id),           // → body
}
```

`getIndex()` 与 `getUnit()` 都先查本地缓存，再回源。

### 本地缓存

IndexedDB 库 `indo-learn`，一个对象仓库 `units`，主键 `"<module>/<id>"`，值
`{ body, version, fetchedAt }`；另一条 `"__index"` 存清单。

- 命中且 `version` 等于本地记的全局版本 → 直接用，不发请求。
- 版本变了 → 清空整个仓库，重取。版本是全局的，逐条比对不值当。
- 没网且缓存命中 → 正常使用（**看过的能离线复习**，这是明确要保的体验）。
- 没网且缓存未命中 → 抛 `offline_uncached`，UI 提示「这部分还没下载过，联网后再打开」。

**明文存**，不加密。内容已经在这台设备的屏幕和内存里，再用一把同样存在这台设备上的
密钥加密一遍，挡不住任何拿到设备的人，只是让代码变复杂。

### 视图改造

`app.js` 里 18 处 `getPacks()` / `getDialogs()` / `getGrammar()` / `getCourse()` /
`getRoots()` / `getListening()` 的整包取数，改成两类调用：

- **列表页**（首页、词包列表、对话列表、语法目录、教材目录）→ `getIndex()`
- **详情页**（某个词包、某段对话、某个语法模块、某个教材单元）→ `getUnit(module, id)`

`guard()` 那层错误兜底保留，新增 `offline_uncached` 与 `rate_limited` 两种提示文案。

还有一处 UI 行为要改：今天没解锁的人什么也点不开，现在 free 单元不需要登录，
**首页在未登录状态下也要能进这几个单元**。做法是把「未解锁 → 直接跳解锁页」改成
「未解锁 → 正常渲染首页，点到 paid 单元时才跳解锁页」，解锁页保持原样。

这是本次改动的大头，也是唯一碰 UI 代码的部分。

## 四、免费层（tier='free'）

未激活、甚至未注册的人能看到的部分：

- packs：初级前 10 包
- dialogs：`sapaan`（打招呼）
- grammar：`phonetic`（发音篇）
- 其余全部 `paid`

tier 写在 `content-src/free-units.json` 里（一份 id 清单），由推送脚本读取写进 D1。
以后调整免费范围只改这个文件重推，不动代码。

## 五、下线清单

| 删掉 | 原因 |
| --- | --- |
| `data/*`（含 v5–v13 全部旧版本目录、keys.json、manifest.json） | 内容不再随站点走；顺带砍掉站点 8 MB |
| `lib/provider.js`（共享密码 provider） | 它靠的静态密文没了 |
| `lib/crypto.js` 里的 KEK / CEK / wrap / unwrap | 只服务于共享密码模式 |
| `tools/pack-content.mjs`、`tools/push-content-key.mjs` 及其测试 | 打包流程整条退休 |
| D1 的 `content_keys` 表、`/content-key` 路由、`currentContentKey()` | 同上 |
| `lib/config.js` 的 `AUTH_MODE` 分支 | 只剩一种模式 |
| README「发布铁律」第 1、2 条与发布流程的五步 | 换成一步 |

`server/src/crypto.js`（口令哈希、会话签名）**不动**，那是账号体系的，跟内容加密无关。

## 六、新工具与发布流程

`tools/push-content.mjs`：读 `content-src/`（复用 `check-content.mjs` 的校验），按第一节
的粒度切成单元，读 `free-units.json` 标 tier，批量 upsert 进 D1，最后更新 `content_meta`
的版本号。支持 `--dry-run` 打印将要写入的单元数与总字节数。

新发布流程：

```bash
node tools/check-content.mjs
node tools/push-content.mjs --version c2
```

改代码仍照旧：`git push`（GitHub Pages）+ `bash tools/deploy-pages.sh`（Cloudflare Pages）。

## 七、迁移与回滚

一次性切换，不做双轨：

1. 建表、灌内容（`push-content.mjs --version c1`），此时线上仍是旧前端，无影响。
2. 手工验证：匿名取 free 单元、登录取 paid 单元、无 token 取 paid 单元被 401、
   刷 401 次触发 429。
3. 发前端 + Worker 新路由，两个站点都发。
4. 观察一天后再删 `data/` 与旧代码（分开一个 commit，方便回滚）。

回滚窗口：第 4 步之前，`git revert` 前端那个 commit 即可，D1 里的 `content_keys` 和站点上
的 `data/` 都还在。第 4 步之后不再保留回滚路径——留着两套就等于防拷贝没做。

老客户端（Service Worker 缓存里还是旧壳）：外壳是 network-first，联网即拿到新代码；
彻底断网的老客户端仍能用本地缓存的旧密文，直到它联网为止。

## 八、测试

- `server/src/content.test.mjs`：路由的六条访问规则各一例，限流边界（第 400 次通过、
  第 401 次 429），匿名只见 free。
- `lib/server-provider.test.mjs`（`tools/` 下现有测试风格）：缓存命中不发请求、版本变了
  清库、离线未缓存抛 `offline_uncached`、401 清会话而网络错误不清。
- `tools/push-content.test.mjs`：切分粒度与单元数、tier 标注、`--dry-run` 不写库。
- IndexedDB 在 Node 里没有实现，provider 测试用一个内存假实现（与现有测试注入
  `storage` / `fetchJson` 的做法一致）。

## 九、风险

| 风险 | 应对 |
| --- | --- |
| Workers 免费额度 10 万请求/天 | 单元请求走 IndexedDB 缓存，同一用户同一单元只取一次；`/content/index` 加 `cache-control: private, max-age=300` |
| D1 免费额度 500 万行读/天 | 一次单元请求 = 1 行读，量级差三个数量级 |
| 印尼网络不稳 | 缓存优先 + 失败重试一次；已缓存的内容完全不受影响 |
| 内容清单泄露（index 暴露全部标题） | 接受。标题本来就在 `lib/catalog.js` 里公开，正文才是要保的 |
