# 中级词包扩充设计

日期：2026-08-18

## 目标

给「中级」补词条，让它从整级「准备中」变成可用。第一批 10 包（100 词）先上线验收，
确认体例后再补剩下 90 包。高级 60 包本轮不动。

## 现状

- 初级：100 包 / 1000 词，词条在 `content-src/batches/batch-01..10.json`，
  经 `merge-batches.mjs` 合入骨架 → `content-src/packs.json` → `pack-content.mjs` 加密。
- 中级 / 高级：只有主题骨架，没有词条。骨架现在写死在 `lib/catalog.js` 的 `UPPER`
  里（`{t, u}` 两个字段），与 `reference/packs.js` 里的完整骨架脱节。
- 开放粒度是「级」：`LEVELS[].ready` 一个布尔控制整级，做完 10 包也点不进去。

## 设计

### 1. 开放粒度下沉到「包」

- 删掉 `LEVELS[].ready`。某个包有没有词条（`words.length > 0`）决定它可点还是灰显「准备中」。
- 分级页计数改为「已开放 N / 总数 M 主题」。
- 中高级骨架改为从 `reference/packs.js` 提取的完整骨架，字段与初级一致：
  `id` / `title` / `subtitle` / `theme` / `stage`。有稳定的包 id，中级词条才能走
  和初级同一套 `batches/` 流水线。
- `extract-packs.mjs` 参数化 level，一次导出三级骨架。

### 2. 骨架与词条拆分

| | 放哪 | 加密 | 内容 |
|---|---|---|---|
| 骨架 | `lib/catalog.js` | 否 | 三级 260 包的 id / title / subtitle / theme / stage |
| 词条 | `data/<version>/packs.enc` | 是 | `{ 包id: [词条…] }` |

- 主题名不敏感，且 UI 要靠它显示「准备中」的包，所以骨架走明文。
- 补词条只重打加密包，不动骨架；骨架调整不需要重新加密。
- App 按 catalog 顺序遍历，用包 id 去词条表取词，取不到即「准备中」。
- 初级现有 1000 词用脚本迁移到新结构，不手改。
- 连带改动：`provider.js`（getPacks 返回词条表）、`check-content.mjs`、
  `pack-content.mjs`、`merge-batches.mjs` 及各自测试。

### 3. 第一批 10 包

按 `reference/packs.js` 原本的 stage 顺序取前 10，不跳号：

```
01 人际/亲友关系   02 年龄/人群年龄   03 性格/人的特点   04 情绪/细腻情绪
05 交流/说话互动   06 语气/说话方式   07 时间/时间安排   08 频率/经常偶尔
09 办公/职场基础   10 办公/任务进度
```

词条沿用初级五字段：`word` / `pos` / `zh` / `example` / `exampleZh`。

标准：

- 与初级 1000 词零重复，脚本硬校验，撞词即换。
- 收中级该有的派生词（`membeli`、`pekerjaan`、`kesibukan`），词根词不排斥。
- 例句 6–12 词；用词限制在「初级 1000 词 + 本包新词」范围内，不用没教过的词解释新词。
- `pos` 沿用初级的中文词性标签。
- 中译口语化，不用翻译腔。

### 4. 校验

`check-content.mjs` 增加两条硬校验，不过不许打包：

- 跨级重复词：中级词条不得与初级词条重复。
- 例句用词越界：例句里出现「初级 + 本包」以外的生词时报警告（列出词，不阻断）。

## 发布

1. 迁移结构 + 10 包词条 → 打包 v3 → 推 main → GitHub Pages。
2. 用户在线上验收（这是他唯一的验收途径）。
3. 确认后补剩下 90 包，再打一版。

密码不变。内容版本每次发布递增（v3、v4…），Service Worker 缓存名同步递增，
否则用户吃旧缓存看不到新内容。

## 不做

- 高级 60 包（下一轮）。
- 词条字段扩充（词缀拆解、搭配短语）—— 会牵动 UI、校验、审校表，本轮不碰。
- 学习进度记录（现有设计就是不记进度）。
