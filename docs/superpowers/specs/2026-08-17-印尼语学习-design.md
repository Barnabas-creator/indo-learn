# 印尼语学习 — 设计文档

日期：2026-08-17

## 一句话

一个纯前端离线 PWA，包含单词包、场景对话、语法学习三个模块，内容用密码加密，部署到 GitHub Pages。

## 背景

起点是微信小程序「bahasa印尼语单词本」（appid `wxc33a21a765ad94f7`）。该小程序的单词包功能是本项目的灵感来源。

已对其 PC 微信缓存包做过解包分析（`reference/` 下保留了解包结果与工具），结论：

| 内容 | 是否可从包中提取 |
|---|---|
| 语法课程（词缀体系、例句、418 个 SVG 插图） | 可以，全在本地包内 |
| 单词包骨架（260 个包的标题/副标题/分级/顺序） | 可以 |
| 2600 个词条本身 | 不可以 — 在微信云开发 `words` 集合 |
| 阅读文章 | 不可以 — 同为云端 |
| 场景对话 | 该小程序没有此功能 |

本项目与已有的 `~/kartu-kosakata`（印尼语单词卡 PWA）是**两个独立项目**。前者定位词根/词组精讲，本项目定位主题速刷 + 对话 + 语法。

## 范围

首个版本：

- 单词包：初级 100 个包 × 每包 10 词 = 1000 词条
- 场景对话：10 组
- 语法学习：从小程序包提取的全部课程内容

明确不做：中级/高级单词包、阅读库、排行榜、打卡、生词本、账号系统、任何进度记录。

## 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 形态 | 纯前端 PWA | 手机为主要使用场景，零后端零成本，离线可用 |
| 进度记录 | **完全不做** | 用户明确要求。包即分类目录，每次从头刷 |
| 文件组织 | 外壳代码 + 独立数据文件 | 体量远超单文件可控范围；也是内容加密的前提 |
| 发音 | Web Speech API `speechSynthesis`，`lang: 'id-ID'` | iOS Safari 自带印尼语音色；Android 需 Google TTS 印尼语包 |
| 配图 | OpenMoji SVG 子集 + 主题图标兜底 | 免费（CC-BY-SA-4.0）、离线、跨平台一致、单图约 2.4KB |
| 内容保护 | AES-GCM 加密 + 密码派生密钥 | 静态站唯一真正有效的方案 |
| 部署 | GitHub Pages | 与 `kartu-kosakata` 一致 |

### 被否决的方案

- **Adobe Stock 配图**：搜索仅返回低清缩略图，正式使用需授权额度；且连接器明确限制批量处理不超过约 20 个文件，1000 张不可行。
- **AI 逐词生成配图**：1000 张在时间和体积上都不现实。
- **纯 Emoji 配图**：iOS/Android 显示不一致，抽象词无对应字符。
- **前端明文口令**：`if (password === 'xxx')` 形同虚设，查看源码即可绕过。

### 内容访问接口

所有内容访问只经过一个接口，为将来切换到服务器留出空间：

```js
provider.unlock(password)   // 静态实现：解出 CEK ／ 将来：换取短期 token
provider.getPacks()
provider.getDialogs()
provider.getGrammar()
```

今天只有 `StaticEncryptedProvider` 一个实现。将来若上服务器，新增 `RemoteProvider` 替换，UI 层不改动。

## 模块

### 单词包

首页网格展示 100 个主题卡：图标 + 主题名 + 副标题 + 词数。

点进包后是 10 张词卡，左右滑动切换，点卡片翻面。

- 正面：印尼语词 + OpenMoji 配图
- 背面：中文释义 + 词性 + 例句 + 例句翻译
- 喇叭按钮朗读印尼语

无进度、无解锁、无"继续"状态。每次进入都从第 1 张开始，100 个包全部可点。

### 场景对话

10 个场景：打招呼、买东西、点餐、问路、看病、坐车、租房、银行、学校、教会。

每个场景一段 8–12 轮双人对话。逐行显示印尼语 + 中文 + 喇叭按钮，另有整段连续播放按钮。页面底部列出本场景关键句与生词。

### 语法学习

沿用小程序的词缀体系，两种页面：

- **词根家族互动**：给定词根（如 `lihat · 看`），列出加不同词缀后的形态（`melihat` / `dilihat` / `terlihat` …），每条带释义、印尼语例句、中文翻译、音变说明
- **课程页**：按章节顺序展示讲解文本与配图 SVG

## 内容保护

### 打包时（本机脚本，产物提交，脚本输入不提交）

```
CEK            随机生成，256 位
data/v1/*.enc  AES-GCM(明文 JSON, CEK)，每个文件独立 IV
KEK            PBKDF2-SHA256(密码, 随机 salt, 250000 次迭代)
keys.json      { version, kdf: { salt, iterations }, iv, wrapped: AES-GCM(CEK, KEK) }
manifest.json  { contentVersion: "v1" }        ← 明文，不加密
```

AES-GCM 自带认证标签，密码错误时解密直接抛异常，无需另存校验值。

### 运行时

1. 读 `manifest.json` 取当前版本号
2. 读对应 `keys.json`
3. 提示用户输入密码
4. PBKDF2 派生 KEK，解出 CEK
5. 用 CEK 解密 `data/<version>/*.enc`

**明文只保留在内存中，绝不写回磁盘。** 一旦落盘，密码轮换即失去意义。

本地仅存 `{ cek, expiresAt, contentVersion }`。以下三种情况重新要求输入密码：

- 解锁过期（默认 30 天）
- `manifest.json` 的 `contentVersion` 变化
- `keys.json` 的 `version` 变化

### 密码轮换

换密码时**必须同时更换 CEK**并重新加密全部内容，版本号递增：

```bash
node tools/pack-content.mjs --password '新密码' --version v2
```

只更换 `keys.json` 而复用同一个 CEK 是无效的 —— 保留了旧 `keys.json` 的人用旧密码仍能解出同一个 CEK，进而解开新数据。重新加密几 MB 内容只需数秒，代价可以接受。

### Service Worker 缓存策略

这一部分写错会让密码轮换完全失效：

| 资源 | 策略 | 理由 |
|---|---|---|
| 外壳（html / js / css / svg） | cache-first | 内容不变，离线需要 |
| `data/<version>/*.enc` | cache-first | URL 带版本号，本身不可变，缓存安全 |
| `manifest.json` / `keys.json` | **network-first**，网络失败才回落缓存 | 联网时必须能看见新版本 |

### 安全边界（明确记录，避免日后误解）

- 纯静态离线应用**做不到真正的吊销**。用户一旦下载过加密包并拿到过密码，那份数据就永久在其手中，更换密码不影响他已持有的副本。
- 密码轮换只保护**此后发布的内容**。
- 离线状态下应用会回落到缓存的旧 `manifest.json` 与 `keys.json`，此时旧密码仍然有效。要做到离线也立即失效，在物理上不可能。
- 拿到密码的人可以导出明文并转发。加密挡的是随手复制，挡不住蓄意获取。
- 要实现即时吊销，唯一途径是服务器下发短期令牌，即上文预留的 `RemoteProvider`。

### GitHub Pages 相关

仓库公开即意味着 `data/*.enc` 公开 —— 这正是本设计的模型，加密本身就是访问闸门。

但以下内容**不得提交**：

- 打包脚本的明文输入（生成好的词条 JSON 原文）
- 密码本身
- `reference/` 解包所得资料

`.gitignore` 需覆盖上述路径。

### 生成内容的质量约定

印尼语词条与例句由 AI 生成，存在不地道乃至出错的可能。每批 10 个包交付一次，由用户抽查，发现问题即改。不视为可直接使用的成品。
